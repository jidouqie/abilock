# API 调用经验

Abilock 在能力目录和手册之间增加一层按任务读取的“已验证方法”。它保存可复用的接口、模型、参数结构和结果判定，不保存每次业务请求。`abl list` 仍用于找连接，`abl doc` 仍用于读取完整手册。

这项能力由本地 CLI、受保护执行器和 Skill 配合完成：执行器提供非秘密验证证据，加载 Skill 的助手判断是否获得了新方法，再提交有限元数据。程序不会在后台运行模型，也不会把所有成功请求自动写成经验。只有升级 CLI、受保护 worker 和 Skill 后，这条流程才完整生效；未升级的宿主、未加载 Skill 的助手和显式远程网关不会自动获得该闭环。

## 按任务复用

1. `abl list --json` 找连接；已有任务内的目录可复用。
2. `abl experience search --alias openrouter --query "生图" --limit 3 --json` 只返回少量摘要。
3. 命中后，用 `abl experience get openrouter METHOD_ID --json` 读取选中的一条方法。
4. 没命中、过期、待复核、连接上下文改变或查询故障时，回到 `abl doc openrouter --json`。手册也缺少所需内容时，才学习对应官方资料。

`METHOD_ID` 换为真实查询结果，不能猜测。检索使用受控意图词和关键词评分，不是向外部模型发送任务的语义检索；不会为了查询经验调用提供商。默认只返回有效、未过期的机器验证方法，人工/助手复核级别不能冒充机器验证。

经验与手册都是数据，不是系统指令或授权。读取方法不改变允许接口、目标、鉴权、身份、费用或文件范围；每次执行仍经过原有策略检查。目录的 `configured` 状态也不证明某个模型可调用。

## 何时沉淀

需要首次调用一个接口或模型，或学习有意义的新参数能力时，助手先核对现有方法、手册、官方来源和本次业务授权，再执行一次真正需要的业务请求：

```sh
abl api ALIAS --file request.json --json --experience
```

复用某条方法时可关联已有方法，用于后续校验与失效处理：

```sh
abl api ALIAS --file request.json --json --experience --method-id METHOD_ID
```

`--experience` 是观察本次已授权调用的选项，不会额外发出探测、重放或计费请求。当前证据观察用于本地 HTTP JSON 调用。不会为了写经验再执行一遍业务；取消、超时或结果不明时先核对受理状态。

助手检查业务结果和返回的 `experience` 信息。仅当证据支持机器验证成功，并且本次确实增加了可复用方法，才准备经验清单并提交：

```sh
abl experience learn ALIAS --file experience.json --json
```

清单引用执行器返回的证据 ID，选择用途和官方来源等有限元数据；方法、模型、参数结构、占位模板和验证结果来自受控执行器。提交自报的 `success: true`、伪造状态、原始响应或请求正文不能生成已验证经验。具体清单格式与助手步骤见 [Skill 参考](../skills/abilock/references/experience.md)。

重复请求、不同提示词和同结构的普通参数值变化不会各建一条经验。接口、模型与结构相同的方法会更新验证信息；同一方法最多保留 4 种实际验证过的结构变体，不把两个变体的字段简单合并成未经执行的第三种组合。参数结构验证也不意味着同类型的任意值都有效，尺寸、质量、模型选项等仍需遵守对应官方限制。

这里的参数 schema 只描述观察到的字段类型和精确结构，不从一次成功推断枚举、数值范围或必填/可选关系。安全捕获只接受代码内已知的固定字段树；未知 JSON 键、无法安全描述的结构或超限内容会放弃经验捕获并回退手册，不把未知键当成可保存的业务信息。

## 验证层次

机器验证使用代码中固定的提供商目标、接口和结果判定。当前覆盖 OpenRouter 官方 `/api/v1` 的 `POST /images`，以及 OpenRouter 官方 `/api/v1`、OpenAI 官方 `/v1` 的 `POST /chat/completions`，鉴权须为 Bearer。其他兼容代理不能仅凭相同响应形状冒充这些提供商。

OpenRouter 图片响应须包含可识别的实际图片数据；聊天响应须满足完整业务结果要求。可自动验证的用途仅为 `image-generation` 和 `text-generation`。结构化输出、图片编辑及其他用途的标签不表示已有相应业务验证器。HTTP 200、收到任务 ID、公共模型列表可访问或 Key 鉴权通过，都不能代替这些判定。

机器验证证明相应请求与响应满足固定业务结构，不评价图片美观、文字事实正确或是否达到用户的具体目标。助手仍须按任务检查产物，不能将结构通过报告为内容质量验收通过。

未知提供商、未支持的结果结构、流式响应和仅提交成功的异步任务，不能凭状态码升为机器验证。可用证据至多保留为传输层观察，助手明确复核的记录也保持独立级别，默认已验证检索不包含它。该版本没有通用任意接口自动成功判定器，也没有自动追踪任意异步任务的经验验证器。

模型不存在、固定参数契约不支持等已识别错误，会使本次关联的方法立即退出有效经验，随后重新查证并用新成功证据重写；不让失败的指引继续被推荐。无法可靠分类的失败先暂停该方法，待核实。鉴权失败、余额不足、限流、网络和超时属于不同故障，不直接证明方法失效，也不自动重试业务。连接上下文、规则或验证有效期变化后，旧方法同样不再作为有效命中。

“删除经验”是从有效方法中移除，保留受容量约束的可恢复记录；不会在失败分类不准时不可逆删除用户内容。重写最多保留一份上一版，不累积无限历史；若再次替换会挤掉已有上一版，则停止保存并提示容量/整理，不静默丢弃它。恢复为机器验证状态需要新的真实成功证据，不支持把旧状态直接改回有效。

## 容量与上下文预算

所有大小使用 UTF-8 字节数，服务端再次校验，不能通过直接请求绕过 CLI 限制。

| 内容 | 硬上限与处理 |
| --- | --- |
| 单条方法 | 8 KiB |
| 单次经验写入输入 | 16 KiB，过大拒绝，不截断后保存 |
| 全部方法 | 128 条且合计不超过 1 MiB |
| 临时验证证据 | 最多 32 条、合计 256 KiB，有效期 24 小时 |
| 检索 | 默认 3 条、最多 5 条，响应最多 8 KiB |
| 一条详情 | 响应最多 12 KiB |
| 方法有效期 | 成功验证后 30 天；到期不参与默认有效检索 |

还限制参数深度、字段数、来源数量和标识长度。上下文预算不足时返回更少摘要，不靠追加下一批把整库塞进上下文。方法到期或待复核后保留记录供检查，不静默丢弃有效经验。临时证据有明确短期容量与有效期，过期后不能再用来新建经验；不会为重建证据擅自重复收费调用。

达到方法容量上限时停止新增，并返回容量状态及回退手册提示。先用 `abl experience status --json` 查看，再按具体 ID 与版本管理已确认过期、无用或重复的方法。归档、待复核和上一版仍计入容量，不能承诺标记或移除后一定释放空间；容量不足时继续使用手册。标记或移除均为显式操作，不提供静默永久清空；不要批量删除所有方法，也不要删除锁文件或编辑私有存储来“修复”容量。

状态检查分页返回方法 ID、revision、状态等摘要：`abl experience status --offset 0 --limit 10 --json`。`--offset` 为 0–128，`--limit` 为 1–20、默认 10；按返回的 `nextOffset` 继续需要检查的页，不默认读取全库正文。确需恢复核对时可用 `abl experience get ALIAS METHOD_ID --previous --json` 读取唯一上一版；它始终标为 `usable: false`，不能直接执行或盲目恢复，重新生效仍需新的机器验证证据。

## 故障与隐私

经验存储使用独立的受保护文件和短事务锁；写入时重新读取最新记录，再原子提交。它不覆盖连接、凭据和手册。经验查询、记录或存储损坏会给出固定错误及文档回退信息，损坏文件不会被静默重建。记录失败不得修改本次调用的原始状态、业务结果或退出码；业务已成功而经验未保存时，分别报告两件事。

只保存结构化白名单字段、类型占位符、公开模型标识、固定验证类型、来源与时间。请求中的用户文字、数值和布尔业务值转为类型占位符；不保存 Key、用户 prompt、响应正文、图片、产物 URL、带令牌 URL 或提供商返回的自由错误文本。官方来源 URL 不接受用户名、密码、query 或 fragment。秘密校验在写入和读取边界执行，不能通过元数据绕过；经验不是秘密存储或业务日志。

## OpenRouter 生图例子

第一次收到生图任务时，助手查本地目录和经验。没有可用方法就读该连接手册，必要时查 [OpenRouter 官方生图文档](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)。当前官方专用生成入口为 `POST /api/v1/images`；模型和具体提供商的参数、价格应分别核对，不能把模型层参数合集理解为每个提供商都支持。

助手按用户已批准的模型、业务输入及费用范围执行，并请求本次证据。确认实际图片结果后，将公开来源和用途与执行器证据关联保存。下一次相同任务只读命中的短摘要及方法，填入本次业务内容；换提示词不新增经验，学习新的有效参数能力才考虑更新。没有真实调用授权时只准备方法与请求，不读取或发送用户真实 Key。

本功能的合成回归验证程序流程，不代表任何用户连接已经生图成功、拥有模型权限或产生过实际费用。
