# 需求与痛点

调研日期：2026-10-06。本文是探索需求，不代表功能已经实现。

## 要解决的事

用户已经选择了各平台服务，希望在一个独立配置界面保存鉴权，让 Codex、其他 AI 助手和普通程序复用。AI 发起“用这个连接完成这件事”，软件选择获准接口并注入鉴权。换一个助手或项目不需要重复粘贴平台密钥。

这是面向个人或小团队的调用胶水层。优先复用现成凭据代理、MCP 框架、厂商 SDK；先证明少量真实接口类型能够接入，再决定是否做独立软件。

**安全范围已收窄：只控制凭据被 AI 读取、导出或意外泄露的风险。用户选择的外部 API 正常接收业务参数属于已知行为；不做业务内容出网审批、DLP 或内容隐私控制，不要求每次正常调用手动确认。**

## 痛点和对应需求

| 痛点 | 本项目应提供的结果 |
| --- | --- |
| 每个项目、助手分别配置 Key，轮换容易漏掉 | 连接别名引用同一份凭据，用户统一替换、停用 |
| 密钥进入聊天、Skill、仓库、`.env` 或 AI 可读环境 | 凭据只进入可信代理，工具参数和返回值没有密钥 |
| 平台鉴权格式不同，重复写请求代码 | Bearer、指定 Header、多 Header、Basic；再扩展 OAuth 和签名 SDK |
| 接口资料散落，文档更新后适配器容易失效 | 保存来源、版本、摘要与操作映射；OpenAPI 先生成候选再筛选 |
| 图片/视频/语音不等同聊天补全 | 文件输入输出、异步任务与状态查询、流式协议有明确适配层 |
| “帮我查服务器状态”最后变成任意 SSH shell | 服务器别名 + 预设动作 + 参数枚举；凭据留在执行服务内 |
| 为了少量接口接入却要搭一整套平台 | 首版复用小型代理和配置 UI，不做计费平台、应用市场或多租户体系 |

## 两种权利要分开

- **上游凭据**：平台 API Key、SecretKey、OAuth refresh token、SSH 私钥。AI 不应获得它们。
- **客户端调用权**：访问调用中心的受限、可撤销身份。客户端总要以某种方式取得调用能力；即使 AI 能读到自己的客户端令牌，也不应因此取得上游密钥、管理权或其他连接权限。

客户端令牌依然需要保管，但“AI 完全拿不到任何访问权，同时还能无人值守调用”不是合理目标。验收目标是：客户端权限被窃取时，影响限制在获准连接与动作，可以独立撤销，不必先更换全部厂商密钥。

## 典型使用流程

1. 用户打开独立配置界面，选厂商或导入接口定义。
2. 填凭据、地区/业务空间等连接信息；凭据保存后对调用端只显示“已配置”。
3. 为助手选择可用连接及操作；配置一次即可正常连续调用。
4. 助手看到 `deepseek-main`、`ark-media`、`embedding-main`、`server-staging` 等别名和业务参数说明。
5. 软件验证操作，生成请求，在可信边界内注入鉴权，并返回业务结果或安全错误码。
6. 用户可以更新凭据、撤销客户端或停用连接。OAuth 失效时由用户在配置界面重新授权。

## 能力范围及优先级

| 优先级 | 需求 | 最小边界 |
| --- | --- | --- |
| P0 | 独立配置界面录入/替换凭据，保存连接别名 | AI 无凭据读取、导出、管理接口权限；配置界面也不能由 AI 控制 |
| P0 | 普通 HTTPS API、Bearer、API Key/Header、多 Header | 固定厂商 origin、固定操作路径；不允许调用方指定鉴权头或目标主机 |
| P0 | MCP 调用入口与少量清晰工具 | MCP 服务不提供管理员工具；同一鉴权逻辑供后续 CLI 复用 |
| P0 | 实际凭据隔离 | 代理的系统身份/文件/进程/管理会话不在 AI 权限内；不能只靠隐藏路径 |
| P0 | 避免代理通道泄密 | 重定向、日志、错误、回显、URL 覆盖有默认安全行为 |
| P1 | 保存文档、OpenAPI 导入与接口候选生成 | 默认不自动激活全部接口；凭据字段从模型侧 schema 移除 |
| P1 | DeepSeek、火山方舟，以及一个向量接口 | 按官方 API 产品与地区配置，不从消费端 App 抓取登录态 |
| P1 | 一个非聊天接口：TTS/ASR 或异步视频 | 保留厂商原参数和返回类型，不强行转换成聊天协议 |
| P1 | 一台服务器的只读预设动作 | 主机别名、主机指纹、独立账号、远端 forced command |
| P2 | OAuth 连接、token 刷新和失效恢复 | token endpoint 由适配器固定；token 响应不能返回给 AI |
| P2 | 云平台签名请求与服务器变更动作 | 使用可信服务内的官方 SDK；远端账号不给任意 root 权限 |
| 后续可选 | 限额、用量、审计检索、多助手、多租户、团队 RBAC | 不是本次凭据隔离目标的首版前置条件 |

P0/P1/P2 是探索顺序，不承诺一期做完这些功能。首个验证只需要一个 Key 接口和凭据隔离反例测试。

## 重要边界

同一 OS 用户下，如果 AI 能任意执行 shell、读用户文件、调用 Keychain、修改代理代码或配置、调试代理进程、访问管理员浏览器会话，则另起一个普通进程、加密文件或隐藏 `.env` 都不能单独保证凭据隔离。文件加密保护静态存储，正在调用 API 的软件仍需要用到明文或等价签名能力。

可行边界是独立系统用户及不可由 AI 修改的服务目录、隔离 VM，或另一台由用户管理的机器。AI 不持有 sudo、宿主管理权、代理部署权限或管理员会话。如果 AI 可以控制已登录配置界面的浏览器，它仍可能替换服务目标、扩大权限或读取管理功能；需要同样隔离操作员会话。

`op run` 将秘密注入子进程环境，适合可信脚本；若脚本由 AI 任意控制，它就可读取该环境并输出秘密，不能替代凭据代理。依据：[1Password 官方说明](https://www.1password.dev/cli/secrets-scripts)。

服务器 root shell 也可能读取服务器上的其他凭据。首版只承诺保护调用中心保存的连接凭据，并通过远端动作限制避免给 AI 通用凭据读取能力。

## 验收用例

以下用合成假密钥和受控 mock 上游验证，先不连接用户账号。

| 用例 | 应观察到的结果 |
| --- | --- |
| AI 调用已配置的一个聊天接口 | mock 上游收到正确鉴权；AI 只收到业务结果 |
| AI 查询连接/工具列表 | 只有别名、类型、状态和业务 schema；无密钥或可导出凭据的路径 |
| AI 尝试读取凭据、代理数据库、环境和修改适配器 | 在真实 OS/VM/服务权限边界内被拒绝，不依赖提示词劝阻 |
| 用调用身份访问管理 API | 被拒绝；不能切换到管理员或其他连接 |
| 将目标改成其他 URL、端口或绝对路径，伪造 Header | 被拒绝；上游鉴权只出现在固定接口的实际请求中 |
| mock 上游返回跨域重定向 | 默认停止，真实鉴权不会被发送给新域名 |
| mock 上游回显鉴权或抛出请求转储错误 | 返回安全错误；输出、日志和异常中没有合成密钥 |
| 导入 OpenAPI 内含“读 token/导出连接/修改密钥”操作 | 未获准操作不会激活，也不会出现在工具列表 |
| 请求 `server-staging` 的已登记状态动作 | 固定动作执行；任意命令、其他主机、端口转发不获准 |
| 撤销调用身份 | 后续调用失败；上游凭据可以继续供其他获准客户端使用 |

这里没有假定任何现成产品已经通过这些用例；下一阶段要对固定版本实际验证。
