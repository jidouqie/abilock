# 通用 API 调用中心：独立探索项目

状态：**需求与第一轮调研已完成；尚未实现、部署或配置真实凭据。** 调研日期：2026-10-06 UTC。

面向国内用户，让 Codex 和其他 AI 助手通过连接别名、业务参数和获准工具调用用户选择的 API 与服务器。用户在独立配置界面保存鉴权，软件在可信服务边界内注入凭据，AI 不读取上游密钥。

## 先看结论

**优先验证 Infisical Agent Vault + FastMCP + 少量可信适配器。** Agent Vault 已有独立配置 UI、凭据存储和转发注入；FastMCP 提供工具接口与 OpenAPI 起步能力。HTTP 代理和 CA 配置只作用于可信工具服务，AI 通过 MCP 调用，不改用户整台机器或已有项目。

最接近需求的候选：

| 项目 | 作用 | 当前判断 |
| --- | --- | --- |
| [Agent Vault](https://github.com/Infisical/agent-vault) | 现成 UI + 凭据代理 | 首选验证；MIT 核心，Preview；AI 只应取得 proxy 权限 |
| [FastMCP](https://github.com/PrefectHQ/fastmcp) | 薄 MCP 工具层、OpenAPI 候选生成 | Apache-2.0；需筛选 operation、剔除鉴权参数 |
| [Nango](https://github.com/NangoHQ/nango) | OAuth 连接、刷新、通用代理 | 后续备选；当前 ELv2，托管包装有许可限制 |
| [Composio](https://docs.composio.dev/docs/security/token-custody) | 托管连接与服务端执行 | 已确认凭据托管注入模式；公开 SDK 不等于免费自托管完整后端 |
| [ContextForge](https://github.com/IBM/mcp-context-forge) | MCP/REST 网关与工具管理 | 多服务时再考虑，少量个人工具不必先引入 |

这些能力判断依据官方来源；没有产品被本次调研证明已通过本项目全部安全验收。更多候选、许可证、维护时点及取舍见 [开源方案对比](02-开源方案对比.md)。

## 必须明确的边界

- AI 的客户端调用权与上游 API Key/OAuth token/SSH 私钥分开。调用身份可撤销，但不拥有密钥读取或管理权限。
- 同 OS 用户下，能任意执行 shell、改代理配置或控制管理会话的 AI，不能仅靠隐藏配置、Keychain、加密文件或另一个普通进程实现强隔离。需独立身份、隔离 VM 或独立机器，并保护管理会话。
- 正常业务参数发送给用户选择的外部 API 是已接受的行为；本项目只控制凭据泄露，不增加内容出网审批、DLP 或每次正常调用手动确认。
- 仍需防止凭据经错误目标、重定向、回显、日志、错误或任意 SSH 命令泄露。
- 已确认腾讯开发者产品是混元/TokenHub；未找到支持元宝消费端通用 API 的官方资料，不能将元宝 App 列作可接入 API。

## 下一步

做一个 **合成假密钥 + mock 上游 + 单个 MCP 工具** 的最小验证：选定 Agent Vault/FastMCP 版本，证明注入成功，调用者读不了 Key，管理接口、日志、重定向和响应回显不会泄密。先判断现成组合是否够用，再决定要不要写显式请求代理或产品包装。

OAuth 通用连接库、HMAC 云签名、复杂语音协议与 SSH 预设动作按实际需要逐项追加，不假定 Header 注入自动覆盖全部协议。限额、多租户、计费、应用市场和全功能运维门户暂缓。
