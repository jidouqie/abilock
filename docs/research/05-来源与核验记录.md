# 来源与核验记录

研究日期：2026-10-06 UTC。所有请求是公开 HTTPS GET，未使用账户认证、读取环境中的 token、登录控制台、创建资源、购买或发消息。

## 证据如何读

- **正文核验**：读到官方文档内容，并用它支持对应判断。
- **仓库核验**：公开 GitHub metadata、默认分支最近提交、latest release 与 license endpoint 原始响应保存本地；遇到混合许可证另读原文。
- **仅入口/目录核验**：可以确认官方路径或目录存在，但 JS 壳/超时不支持对鉴权细节、全部模型或参数作结论。
- **未确认/已排除**：保留失败记录，避免把旧链接、错误重定向或企业 tag 当成已验证能力。

对“密钥从模型上下文中移除”和“AI 权限范围内无法取到密钥”采用不同结论。现成方案的营销或安全文档只证明设计模式，不能替代固定版本、真实权限配置下的验收。

## 本地原始证据

- [github-summary.json](research/github-summary.json)：仓库、最近提交时间/SHA、许可证检测、latest release、错误。
- [github/](research/github)：14 个候选仓库的完整 metadata/license/release/head 响应，以及 Agent Vault 的限流错误记录。LICENSE 内容是 GitHub 返回的 base64 原文；可对照 response URL 与 SHA。
- [public-link-checks.json](research/public-link-checks.json)：官方 URL 的 HTTP 状态、最终地址、title、内容 hash、大小、正文是否经本次人工核验。`200` 不代表正文已经核验。
- [agent-vault-web-verification.json](research/agent-vault-web-verification.json)：Agent Vault GitHub API 限流后的网页/原始许可证补充。
- [Agent Vault 许可证原文](research/licenses/agent-vault-LICENSE.txt)：公开 raw LICENSE 的本地副本，配合链接检查中的 hash 核对。
- [collect_github.py](research/collect_github.py)、[check_public_pages.py](research/check_public_pages.py)：公开只读采集辅助脚本，不是调用中心原型；没有部署、鉴权配置或凭据读取功能。

文档全文仅作临时阅读缓存，不把大批上游文档全文当成项目交付物。固定证据包括公开仓库响应、许可证及链接检查摘要。重新运行采集会获取新的时点；不要在后续研究中覆盖旧证据而仍沿用 2026-10-06 的结论。

## 已发现的获取限制和排除项

| 项目 | 实际发现 | 本次处理 |
| --- | --- | --- |
| Agent Vault GitHub API | 后追加候选时公共 API 返回 403 rate limit | 用 GitHub release 页面及 raw LICENSE 核验；HEAD 日期保留未确认 |
| GitHub `releases/latest` | Pipedream / OpenSSH 返回 404 | 仅写“此 endpoint 未提供 latest release”，不判成停止维护 |
| FastMCP 历史地址 | jlowin/fastmcp 跳转 PrefectHQ/fastmcp | 使用新地址，保留 metadata 的最终 URL |
| Bifrost latest tag | `ent-v2.2.6-base` | 明确企业 tag；不作为 OSS 免费功能证明 |
| Composio latest tag | SDK 子包 `@composio/openai@0.13.0` | 不当成整个托管平台后端版本 |
| Nango/Pipedream/Infisical/Vault/Unkey | GitHub SPDX 检测 `NOASSERTION` | 读根许可证，区分混合/受限许可；不只用 SPDX 值判断 |
| 火山新版文档 | 旧数字路径重定向，部分页面只返回 JS 壳 | Chat 与视频正文另由公开 HTTP 读取；语音/图片细节保持待核验 |
| Tencent 旧 `/1300/103556` | 实际重定向到无关 EdgeOne 文档 | **排除**；改用 `/1729/111007` 与 `/1729/111008` |
| Tencent 旧 `/1300/80695` | 国内站 404，国际站过大 | 不作为国内接口证据；使用混元正确产品编号及官方迁移说明 |
| Unkey 文档猜测地址 / Teleport machine 页面 | 个别页面 404 或空壳 | 不据此宣称特定凭据代理功能已验证；Teleport 只作后续参考 |
| 腾讯元宝 | 未找到支持消费端通用 API 的官方开发文档 | 不列入可接入厂商；用混元/TokenHub，且不声称“未来不可能有 API” |

## 下一阶段需要实测的事

1. 固定 Agent Vault v0.40.0 或后续选择的版本，验证 proxy 角色不读 Key、管理权限不外露、response echo 和错误不泄密。
2. 固定 FastMCP 版本，确认默认拒绝及去掉鉴权字段后生成的工具 schema。
3. 验证每个非标准协议的签名、OAuth token 回调/刷新、媒体任务或 SSH 动作；未经实测不标“已支持”。
4. 若选择 Bifrost/Nango/托管连接服务，核验所需功能在具体发行版和许可范围内的可用性。

普通公开只读研究已完成；剩余不确定性是后续实现试验的题目，没有账户、购买或部署方面的阻塞被假装完成。
