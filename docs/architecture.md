# 架构

Abilock 按“AI 主操作，人能查看、修改和接管”的原则设计。用户用自然语言交代目标，Skill 引导当前助手查目录、按需读取资料、生成执行参数、核对结果与持续维护用法；CLI 落实受控执行，应用显示同一份持久连接和手册，允许用户微调及完整接管。Skill 是主要产品入口，应用不是要求用户先填大量信息才能交给 AI 的流程前置。

用户提供的《AI助手主导的软件设计理念》适合本项目，已作为本次架构依据。用户桌面原文保持不变；本文件只记录 Abilock 的具体适配。采用其交互和数据原则，不照搬人物、图集等其他业务对象，也不要求用户先完整编写 Markdown。

## 数据与操作

| 内容 | 谁维护 | 保存和使用方式 |
|---|---|---|
| 别名、目标、协议身份、鉴权、凭据 | 用户在应用或配置页填写 | 结构化校验；秘密只由受保护执行器读取 |
| 调用经验 | 执行器提供非秘密证据，助手选择性提炼 | 按任务返回有限摘要，只读取选中方法；不是普通调用日志 |
| 官方文档链接 | 用户填写，或按任务提供公开来源 | 供 AI 获取公开资料，不带凭据抓取 |
| 手册 | AI 整理，人可查看和微调 | 自由 Markdown，页面与 `abl doc` 共用 |
| 接口方法、路径、聊天元数据 | AI 根据已取得的官方证据生成 | `abl learn` 校验后保存；不改变目标、鉴权或秘密 |
| 版本、关联编号、执行状态 | 程序维护 | 用于冲突检查和结果核对，不交给用户手填 |

自由 Markdown 用于表达用法，不用来绕过确定性的执行规则。机器保存清单中出现 JSON 或固定字段，不代表用户需要写这些内容。

## 组件

| 组件 | 职责 |
|---|---|
| Skill | 理解自然语言目标、查目录、检索少量经验、按需读手册、学习公开资料、执行并核对结果 |
| `abl` | 提交结构化请求，接收公开结果；不直接打开凭据库 |
| 受保护 worker | 按固定身份读取凭据、检查目标和操作范围、注入鉴权、处理结果 |
| Store | 保存连接与手册的权威状态，处理短事务和版本冲突 |
| Abilock 应用 | 显示连接、手册和必要配置字段；拥有自己的临时管理会话 |
| `abl config` | 保留原有临时浏览器配置入口 |
| 可信安装器 | 安装固定程序和身份，处理本产品的升级、迁移与注册 |

macOS 使用固定原生启动器和专用 UID。Windows 使用固定原生 Host、专用 SID 和没有自动触发器的按需任务；任务注册本身不等于常驻 Abilock 进程。业务调用没有 HTTP 执行监听。

## 一次任务

1. AI 先查 `abl list`，按用途选择连接。
2. 本地 HTTP 先检索少量有效经验摘要，再读取选中方法；协议或经验未命中时只读本次需要的 `abl doc`，不把全部手册载入上下文。
3. 手册缺失、上下文改变或用户要求更新时，AI 获取对应官方资料并学习。Markdown 保持自由，机器参数由 AI 按任务生成，由软件校验。
4. AI 按已授权任务提交业务参数；worker 在私有身份内加入鉴权。
5. AI 核对完整结果、退出状态和必要的厂商任务 ID。新的已验证方法按 Skill 提交经验；普通成功请求不自动入库。调用完成后 worker 退出。

这条路径的内容理解由用户当前使用的助手完成，Abilock 不在后台运行另一个模型。业务响应返回助手；当前 UI 展示连接、手册与测试状态，不声称是所有外部任务的统一成果或历史面板。

应用不必先打开。应用开着时，也不妨碍独立 CLI 读取和保存手册。关闭应用只结束它自己启动的配置会话；不会按进程名批量清理，也不会接管别的配置程序。

## 代码结构

执行角色只有一个路由（`src/execution-routes.ts`），同时服务按需本地 worker 与显式远程服务；两种传输只保留各自的鉴权、帧格式与错误封装。SSH 终端会话（`src/local-terminal.ts`）同样由 IPC 帧和 WebSocket 共用。协议种类只在 `src/protocol-kinds.ts` 定义一次：服务与网关路由由它生成，适配器表和管理页表单按它做类型检查，CLI 命令映射（`bin/native-kinds.mjs`）由测试核对一致。新增协议时，编译和测试会指出所有尚未补齐的位置。

## 共享状态

页面、CLI 和学习入口通过同一个 Store 保存连接和手册。每次写入只短暂取得跨进程锁，持锁重新读取最新权威状态，检查版本，再原子提交。界面停留期间不持有写锁；网络请求和文档抓取也不占用它。

只读请求刷新状态而不写文件。页面空闲可见时每 15 秒刷新，重新获得焦点时也刷新；也可手动刷新，界面显示最后刷新时间和失败状态。手动与自动刷新不重叠，编辑中的草稿不被后台刷新覆盖。保存已提交但刷新失败时，明确提示已保存，不要求重放写入。

人工改动已学习手册时，同步增加所属连接版本，旧 AI 学习清单会得到版本冲突。AI 必须重读并合并人工改动；不能用新版本号机械重放旧内容。每次覆盖更新还保留同一手册的一份上一版，仅包含标题、来源、正文、版本和时间，不包含连接配置、鉴权、规则或秘密，也不递归保存历史。应用可查看上一版，或把其标题和正文填入当前草稿；当前来源和版本检查不变，用户确认保存才提交。新增或轮换凭据时，当前正文与历史正文都重新脱敏，两个版本的元数据同样校验。当前 CLI 不加载历史正文；只有应用提供查看/填回草稿入口，不提供无限历史或已删除手册的回收站。

当前版本无法校验的记录（例如更新版本新增的协议种类，或手工损坏的字段）不会让整个状态无法加载：它们被单独搁置，不能执行，别名保持占用，凭据仍参与脱敏，之后的每次提交原样写回；管理页列出这些记录，只有用户明确删除时才移除。无法用主密钥解开的密文仍使整个状态拒绝加载，不会被当成单条坏记录隐藏。只读刷新先比较 `state.json` 的文件身份与纳秒时间，未变化时不重新解析、解密和扫描手册；页面空闲时只轮询一个状态版本号，变化后才重新加载完整列表。

Markdown 文件只是导出副本。权威保存成功而副本失败时，返回 `DOCUMENT_EXPORT_PENDING`，后续写入或配置启动重建副本；不能当作整次保存失败而重放。

## 有界经验与兜底

经验是目录与手册之间的可选索引层，存储在同一受保护数据目录下的独立文件，通过独立短事务锁原子保存；它不复制连接、凭据或手册。默认只检索当前有效的机器验证方法，详细规则见[调用经验](experience.md)。

单条方法 8 KiB，单次写入 16 KiB，全部方法连同归档和上一版最多 128 条且不超过 1 MiB；一次检索最多 5 条、8 KiB。普通值变化不会新建方法，结构变体受限。已确认失效的方法退出活跃检索，用新成功证据重学；不确定先暂停，临时网络或额度错误不直接删正确方法。历史与临时证据都有明确容量，容量满停止新增并回到手册，不静默丢弃有效内容。

执行器只捕获白名单结构、占位符和有限验证结果，不保存用户 prompt、响应正文、图片或秘密。只支持固定验证器的调用可自动获得业务结构验证，任意 HTTP 200 不能自报为成功。记录故障单独报告，不改变业务调用结果或自动重试。经验文本也不能改变任何执行边界。

## 安装与管理

项目仓库是 https://github.com/jidouqie/abilock。源码安装入口在当前干净提交的临时副本构建和验证，再调用同一平台安装器；私有仓库访问、已有依赖和系统授权是实际前提，不把一句提示词理解成所有助手都能免确认安装。完整平台包准备应用、CLI、Skill 和运行依赖。系统管理员授权限于安装本产品的身份与受保护程序，不给 AI 任意管理员能力。新实例的管理密码由用户在受保护窗口填写；以后进入应用或配置页仍需登录。

`abl app` 打开独立窗口；`abl config` 保留临时浏览器页面。两者使用同一配置功能，窗口只显示直接名称和必要字段。SSH 私钥可选择本地文件或粘贴；文件只进入当前配置表单，不单独上传或记录日志。

macOS 及 Windows 的入口、权限和恢复差异见[本地隔离](security/local-isolation.md)。Windows 安装脚本使用英文 ASCII；已测试的 PowerShell 版本及尚未实装的范围见[README](../README.md)。测试包、策略自测或模拟异常都不能代替专用身份下的真实拒绝读取与成功调用验收。

## 应用里的接管

连接页按 API、SSH、数据库等分类；可搜索别名、名称、类型、地址和简介。搜索只用于定位公开连接资料，不读取凭据或展开全部手册。已有连接可以编辑、改名、启停或删除；手册页直接提供“编辑连接”，改名后跟随新的别名。

手册显示更新时间，并提供自由 Markdown 编辑和上一版查看。发生冲突时，用户可在保留草稿的同时查看最新手册；明确选择以新版本继续编辑后，仍需普通保存及版本检查，不自动提交。关闭未保存的手册草稿前提示确认。

“已配置”只表示本地必要配置齐全，不表示刚刚测试过上游。应用内显示可选中的公开文档地址，供用户复制到浏览器；原生窗口继续限制外部导航。

2.2.11 开发版统一连接测试的计划、执行与结果。管理服务从已保存记录选择代码内固定探针，返回鉴权、服务响应或未验证层次；可能产生存储请求费用时，界面先展示范围并要求一次明确确认。测试不扩展业务规则、不写连接、不持长事务锁。目标或凭据变更后的旧结果、取消后的迟到结果都会失效。SSH 测试单独要求可信主机指纹，不自动接受未知主机；普通 SSH 兼容行为仍按既有执行路径处理。详见[连接测试](connection-testing.md)。
