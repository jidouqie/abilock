# 密码与数据恢复

管理密码用于进入配置窗口，主密钥用于解密凭据，两者不同。没有默认管理密码、CLI 重置或秘密导出入口。

## 仍能登录

在应用或配置页改密。旧会话失效，连接、手册和上游凭据保持不变。

## 本地隔离版

macOS 私有数据在 `/private/var/db/abilock`，Windows 在系统已知的 `%ProgramData%\Abilock\private`。忘记管理密码或数据损坏时由可信管理员处理，助手不自行读取私有配置或执行重置。

处理前确认活动调用和配置窗口已正常退出，并由可信用户在助手无权访问的位置备份完整私有目录及原主密钥。不能通过删密码记录、删私有目录、生成新主密钥或切换同用户模式恢复。日常启动入口会拒绝缺失/损坏的认证状态。

更新 Skill 或客户端不重置数据，也不证明受保护程序已升级。完整安装包用户重新运行相应可信安装入口；macOS 原有 CLI 还可用 `abl config` 升级。Windows 使用 `Install-Abilock.ps1`。先预检再授权，不为排障反复重装。

macOS 的可信安装器覆盖已安装版本前，会在安装锁与运行门锁内确认没有活动调用，然后将完整私有数据目录及旧受保护程序（包括原应用、manifest）复制到 `/private/var/db/abilock-backups/<随机标识>/`。同版本替换也执行备份。备份根目录与每次备份目录仅 root 可进入，文件仅 root 可读写；原所有者、权限、ACL、扩展属性及内容校验值只存于该备份的私有 manifest。安装器不解析凭据，不把它们输出，也不修改原数据的权限或身份。

备份拒绝链接、特殊文件、跨设备目录、过深或过大目录以及读取时变化的内容；总量上限 64 GiB、200000 个条目、128 层、64 MiB 元数据。空间不足或校验失败会在交换程序目录前停止，不静默跳过文件；不完整备份保留在 root 私有目录。新版本提交前再次核对私有数据内容、身份与权限。公开 `installation.json` 的 `upgradeBackup` 只记录备份目录、版本、文件数和 `dataPreserved`，不包含秘密、私有文件名或校验值。

这些备份独立于安装事务，成功升级与事务清理均不删除它们。没有普通 CLI 读取、导出、删除或自动恢复入口；可信管理员按需处理留存与恢复。此机制保护后续覆盖安装，不补造以前版本的历史备份。`abl config` 只按版本判断升级；需要替换同版本构建时，使用新完整包的 `Install.command`。

## 安装中断

macOS 重新运行原可信安装入口或相应 `abl config` 升级流程；Windows 重新运行同一已验证完整包的 `Install-Abilock.ps1`。安装器只按受保护事务记录确认 nonce、身份与目录，再恢复或继续；未知内容保留并停止。

Windows 新装密码窗口取消后，下次会继续初始化，不把程序已复制当成初始化完成。已有合法密码记录和匹配的主密钥/状态时，安装专用入口可原子修复缺失、空或半写的固定 `admin-auth.v2` 标记；它不改变密码、主密钥或状态。坏密码记录、未知标记内容或身份不符继续拒绝。助手不手动复制、删除这些文件，也不能通过普通 CLI 调用 bootstrap。

此恢复流程已有代码与假值测试；Windows 真实系统安装、断电恢复和升级回滚的整体验收尚未完成，不能用测试模型代替实际安装结论。

## 保存与锁

`service.lock` 只在短写事务期间持有；`bootstrap.lock` 覆盖完整首次初始化。进程结束会释放系统句柄，文件留在原位正常，不手动删除。应用开着不代表写锁被占用；遇到 `CONFIG_BUSY` 等实际事务完成再重读公开版本，不能强停其他用户任务。

`REVISION_CONFLICT` 表示已有更新。重读最新连接和手册后合并，不只修改版本号重放旧正文。当前只保留一份上一版手册。应用可查看并用其标题/正文填入当前草稿，用户确认保存才生效；当前来源、目标、鉴权、规则和版本检查不随历史恢复。默认CLI不返回历史正文，删除手册/连接不会保留回收站。

新增或轮换凭据时，当前手册和上一版的标题/来源均不能含已保管凭据。错误会指出这两个范围，但不回显值。仅修正当前版本仍会留下旧历史；用户可检查上一版，再显式保存已清理的当前版本，让上一版也被这个干净版本替换。正文的已知凭据自动脱敏，无需读取私有数据修复。

`DOCUMENT_EXPORT_PENDING` 表示配置和手册已保存，只有 Markdown 导出副本未完成。页面和 `abl doc` 可读取已提交内容，下次写入或配置启动自动修复，无需再次导入。

## 显式服务部署

以下仅用于可信用户管理、明确启动的旧服务部署，不适用于上述本地隔离版：

1. 停止服务，确认没有其他写入者。
2. 备份完整 `ABILOCK_DATA_DIR` 和原主密钥。可信用户将 `admin-auth.json` 重命名为安全备份；保留 `admin-auth.v2`，不删除旧令牌禁用标记。
3. 保留原配置、状态、文档、工作区、主密钥及执行能力，按原部署方式启动。
4. 在服务实际看到的本机 loopback 管理页重新设置密码。远程代理或宿主容器映射不满足首次设置条件。

具体部署条件见[远程部署](../../deploy/README.md)。

## 丢失主密钥

没有原主密钥就不能解密原凭据。重设管理密码或创建新主密钥不能恢复旧密钥；保留备份，由可信用户确认方案。本版本没有自动主密钥恢复或轮换工具。
