# 本地权限隔离

当前结构是独立应用、CLI 和按需受保护 worker。业务调用不监听端口；配置窗口存续期间临时运行本机管理页面。macOS 使用专用 UID，Windows 实现采用专用 SID。实现、策略测试、真实安装验收应分别报告。

## 安装与升级

完整平台包自带运行依赖。macOS 入口为 `Install.command`，Windows 为 `Install-Abilock.ps1 -BundlePath ...`；先验证公开包、架构与必要系统条件，再请求一次系统管理员授权。授权只限本产品安装，不给 AI 任意管理员权限。

安装器注册应用、CLI 和安装用户的 Skill 入口。新实例的管理密码由用户在受保护窗口填写，没有默认密码；已有密码、主密钥、连接和手册保持。macOS 原有 Node 客户端路线可继续由 `abl config` 检查和升级；Windows CLI 检查到缺安装或旧运行包时指向完整安装器，不在普通执行通道修改程序。

升级等待当前调用和配置会话结束，不强杀用户任务。macOS 使用安装门锁与原子目录切换；Windows 禁止专属任务新启动、确认无活动实例后替换程序。两者都记录受保护事务并保留恢复材料，状态不符时停止，不接管未知身份或重置数据。

Windows 脚本全部英文 ASCII，入口保持 PowerShell 5.1 语法，7.x 实际变更转给系统 5.1，不再次弹 UAC。授权前按内核返回的真实 OS 架构选择包；x64 拒绝 ARM64 包，Windows 11 ARM64 可以使用 x64 仿真包。标准用户可以通过另一管理员账户授权，日常调用仍绑定原安装用户。

## 文件与执行

| 内容 | macOS | Windows |
|---|---|---|
| 程序根目录 | `/usr/local/libexec/abilock`，root 所有 | `%ProgramFiles%\Abilock`，Administrators / SYSTEM 保护 |
| 私有目录 | `/private/var/db/abilock`，`_abilock` UID | `%ProgramData%\Abilock\private`，`_abilock` SID 与管理员/SYSTEM |
| 固定入口 | 原生 `launch` | 原生 `Abilock.Host.exe` |
| 独立运行时 | `node` | `node.exe` |
| 普通 CLI | 固定 wrapper 或已确认客户端 | `runtime\bin\abl.cmd` |
| 启动方式 | 一次性身份切换和监督进程 | 无自动触发器的专属按需任务 |

启动器固定身份、路径和操作，清空继承环境，使用受保护运行包。业务请求通过有界消息进入 worker，鉴权在 worker 内部加入，秘密不通过 IPC 交给客户端。Windows 命名管道核验两端身份，worker 仅提供 Identification 级令牌；bootstrap 管道仅供管理员安装流程，不可由普通用户冒充接收管理密码。

Windows 权限依赖 SID/ACL，不以 `chmod` 或 POSIX mode 代替。原生检查拒绝危险 reparse/hardlink、普通用户可替换保护目录的祖先权限及可修改的程序。安装文件和目录在创建时就设置管理员所有者与 ACL，辅助源码按已校验的同一份内存字节编译，不先校验路径再重新打开执行。

执行通道不能调用管理接口、导出秘密或改目标。`abl learn` 只能保存公开手册、证据支持的接口规则与说明；普通文档编辑不能扩大执行范围。

## 应用、配置和锁

`abl app` 打开独立窗口。应用只拥有自己启动的临时配置进程；关窗口时停止它，不影响独立 CLI 调用。`abl config` 保留浏览器模式，macOS 用用户自己的 Chrome，完成后 Ctrl+C；关标签页不会结束配置程序。二者均不自动登录或代填管理密码。

Store 只在一次提交内持有跨进程锁：持锁重读权威状态、核对版本、原子提交，再释放。页面停留和文档抓取不持写锁，只读请求刷新状态而不修复磁盘。因此 AI 可在应用开着时学习，人工修改和 AI 写入仍有版本冲突保护。 覆盖更新只保留一份上一版公开手册，随同权威状态原子保存；不含凭据、连接配置或执行规则。新增/轮换凭据时当前与历史正文同时脱敏、元数据同时校验。应用恢复仅填入草稿，确认保存仍使用当前revision，不改变执行权限。

macOS 的小型锁组件取得内核锁后退出，由 Node 持有描述符；Windows 锁助手只在事务内持有独占句柄，stdin 结束后退出。稳定锁文件可长期存在，不能按文件存在、PID 或年龄判断占用，更不能删除解锁。Git 同仓库操作另有覆盖文件变更、原生命令与导出的事务锁。

完整 bootstrap 使用独立跨进程锁，不依赖 Store 的短事务锁。认证记录和固定标记采用原子写入；恢复只能在验证已有密码记录、主密钥和状态后修复缺失或半写的非秘密标记，不能重设既有密码。

## 恢复与数据

macOS 安装器只内部处理已知 `~/.abilock` 旧实例；不扫描其他项目或账号。Windows 不自动导入未知旧目录；未确认归属的账号、私有目录或任务会停止安装。

Windows 新装中断后保留 nonce、SID 和阶段。专用账号的随机密码仅在管理员/SYSTEM 专属事务目录中以 DPAPI 密文临时保存，供续建任务；完成后删除。它不是用户管理密码，也不进入公开清单、环境或输出。初始化必须取得可信 worker 回执后才写受保护完成标记，不能因为程序目录存在就跳过首次初始化。

权威状态先提交，再导出 Markdown。`DOCUMENT_EXPORT_PENDING` 表示已保存而副本待重建；后续写入或配置启动修复，页面和 CLI 继续读权威内容，不重复学习。未知备份与过去复制出去的密钥不在安装迁移范围内。

## 保证与验证范围

目标是阻止普通用户下 AI 直接读取密钥、主密钥或篡改受保护代码。结论必须基于真实 OS 身份与内核拒绝、授权假密钥调用成功、结果脱敏和进程退出；模拟异常或管理员勾选声明不能证明隔离。

可信区域包括系统管理员、操作系统、安装来源、用户正在使用的管理窗口以及接收鉴权的上游。AI 任意管理员权限、执行身份 shell、已打开秘密句柄、已登录管理页面控制权，以及恶意上游的任意加密/隐写回显不在普通调用隔离保证内。

macOS 与 Windows 必须各自在目标系统验收。源码中的身份/策略/协议测试和桌面合成窗口用于验证实现，不能单独证明真实专用身份、管理员安装、升级回滚及普通用户权限边界已经成立。Windows 当前仍不能宣称完成整套真实安装隔离验收，也不保证任意未来 PowerShell 版本。当前实际支持和已验收的平台范围见 [README](../../README.md)；用户真实供应商鉴权、模型权限和计费不包含在合成验收中。

`ABILOCK_DEVELOPMENT=1` 只用于同用户假值演练，不提供这些权限边界。Linux 没有当前同等本地隔离安装器；显式远程模式的保证取决于实际部署，任何平台失败均不静默降级。
