# 凭据与隔离威胁模型

2.2.0 提供 macOS / Windows 独立应用和按需 CLI，具体实现与验证范围见[本地权限隔离](local-isolation.md)。业务 worker 内部读取凭据、注入鉴权、返回脱敏结果并退出，不监听业务端口；应用或 `abl config` 存续期间才临时运行本机管理页面。macOS 使用专用 UID，Windows 实现使用专用 SID、固定 Host 和无自动触发器的按需任务。Windows 当前的临时包、假值与原生策略测试不等于真实系统安装隔离已验收。显式远程部署仍可使用；同用户开发模式和未隔离旧部署不提供强隔离。

保护对象：用户录入的厂商 Key、Basic 用户名/密码、管理密码及会话、旧兼容管理令牌和服务主密钥。远程执行能力令牌只授予现有平台能力，需由用户按 AI 的实际需求提供；默认本地模式不要求给客户端执行令牌。

## 本地模式实际保证

显式服务模式的管理和执行端口分别鉴权，本地 CLI 的执行入口不监听端口。执行入口不能读/导出秘密、修改平台或调用管理端。配置只返回鉴权类型与已配置状态；秘密只通过管理 UI 写入并 AES-GCM 加密存储。CLI 的 list/doc/api 只访问执行面；config 通过安全 argv 打开临时公开 UI 地址，app 请求启动独立应用。应用只清理自己启动的配置进程，不接管已有会话或结束其他业务调用。CLI 不含管理 API、密码、上游凭据选项、凭据存储读取或动态代码执行，config 在没有执行令牌时也能工作。

新实例没有默认管理密码，包括 mock。受保护本地安装由可信安装专用入口初始化，密码在用户设置窗口填写，完整 bootstrap 使用跨进程锁和原子认证/标记写入。Windows 恢复先验证既有认证记录和主密钥/状态，只修复固定非秘密标记，不重设密码。

显式服务/mock 的首次设置仍从实际本机同源 UI 进入，要求 8–256 个 Unicode 字符；校验 socket 来源、loopback Host、Origin 与 UI 标记，不相信转发头。`ABILOCK_ISOLATED_BIND=1` 不绕过这项边界。该 UI 设置路径有自身互斥及独占提交，坏记录不会自动重置。当前管理认证仍是 HTTP 同源流程，没有内置 HTTPS 反向代理初始化。

管理密码与主密钥分离：`admin-auth.json` 保存 scrypt 哈希（N=32768、r=8、p=3；32 字节随机盐、64 字节结果），不保存明文，不用于上游加密。`admin-auth.v2` 是禁用旧管理令牌的无秘密迁移标记；第一次成功设置密码后旧令牌被禁用，重启仍保持。旧实例仅在迁移前支持其原 `ABILOCK_ADMIN_TOKEN`，不是新实例默认密码。

管理会话在服务内存中，浏览器收到 HttpOnly、SameSite=Strict Cookie；敏感修改需独立 CSRF 值。8 小时绝对期限、1 小时闲置期限，重启后全部失效。页面的后台轮询带 `x-abilock-background` 标记，不续期闲置期限；只有用户操作产生的请求才续期。登录每来源每分钟 5 次失败后限速，认证操作全局最多 30 次/分钟，同时限制并行慢哈希。UI 修改密码撤销全部旧会话，再建立当前会话；执行令牌不能登录管理入口或变成管理会话。

请求只能发往管理配置的目标与路径。每次 DNS 解析检查所有结果，并将连接固定在已验证的公网 IP，同时保留 HTTPS hostname / 证书验证。禁止私网、loopback、metadata、嵌入 URL 凭据、query 目标覆盖、路径穿越/编码/双斜线/反斜线，以及跨源或降级重定向。开发 mock 的例外仅限显式开启的 127.0.0.1 HTTP。

不将执行端的 Authorization 透传到上游，服务按配置重新注入上游鉴权。拒绝用户覆盖鉴权、Host、Cookie、Forwarded、重复大小写 Header、逐跳 Header 和鉴权 query 字段。响应只转发内容类型及有限元数据，不转发上游 Cookie/Location/任意回显头。日志只写元数据。错误消息不嵌入用户提交值或库的原始网络错误。

输出过滤已配置秘密、Basic/Bearer 完整串及常见 URL/Base64/JSON 编码；流式过滤保留可能横跨 chunk 的前缀。对压缩响应明确拒绝。此过滤能阻止已测的回显泄露，**不能保证恶意上游以任意变换、加密、拆分协议字段或隐写编码秘密时仍被识别**。上游属于管理员信任的目标；若上游本身恶意，它已接收该平台鉴权，输出过滤不能撤销泄漏。滤器可能改变含秘密字节的二进制，正常无匹配的文件保持逐字节一致。

文档抓取不带上游鉴权、执行/管理令牌，不跟随重定向。文档更新函数只写文档字段，不修改平台。UI 以受控 Markdown 渲染展示内容，不执行 HTML/脚本或自动加载外部图片；人可编辑标题和正文，不能借文档编辑改变执行规则。文档内容是外部数据，AI 应忽略其中的指令。管理员可配置域名、路径和文档，属于信任边界。

过滤支持标准 URL/form 表示及百分号十六进制的大小写等价，其他字符保持精确匹配。JSON 的固定分隔语法和 SSE 字段/framing 不被视为凭据回显；业务字符串、字段名、标量及事件内容仍按已知秘密处理。SSE 只缓存当前事件，按空行或 EOF 交付，沿用 100 MiB 单事件与累计上游上限。服务生成的完整 UUID 与已知凭据精确相撞时会重新选择并复验；UUID 中与短凭据巧合的公共字符不会使关联编号失效。

## 不成立的强保证

在同用户开发模式或未隔离旧部署中，若 AI 有无限 shell 或可读同身份文件/进程，就能绕过 CLI API：读取服务环境、文件、内存、修改源码，或手动重置管理密码。AES-GCM 不能抵御同时能读主密钥的主体；慢哈希不保护对运行进程、密码输入或文件写入拥有权限的主体。双端口分离也不提供 OS/network 隔离。开发 mock 不能被称作强隔离。实际隔离验收必须记录不同 UID/SID、真实内核读取拒绝及调用成功；系统管理员及可信配置入口不在普通调用的隔离保证内。

应用 WebView 或浏览器页面内存会暂时持有用户录入值，应用、浏览器/扩展及管理身份属于可信区域；退出或关闭编辑会清空 UI 输入。密码与上游秘密不写 localStorage 或 Cookie；Cookie 只保存不可由页面脚本读取的管理会话。终端中的厂商凭据禁止通过 abl 输入；`.env` 只由可信用户配置主密钥、执行令牌及服务参数，不配置管理密码，不能分享给 AI。config 不自动登录、设置密码或验证上游连接；浏览器打开失败信息不带原始错误或输入值。

忘记管理密码由可信管理员按[密码与数据恢复](recovery.md)处理。重命名密码记录的旧流程仅适用于显式服务部署；macOS / Windows 隔离 CLI 检查既有认证状态，不能照搬该操作。没有 CLI 密码重置、默认密码、远程找回或自动主密钥恢复；遗失主密钥不能靠管理密码恢复。

## 真正隔离部署前提

推荐独立服务主机或可信服务身份：先在服务所在环境的本机 loopback UI 完成首次密码设置，再按实际网络边界开放给可信用户和执行网关。管理页面通过用户控制的本机/SSH loopback 隧道访问；AI 在另一台机器，仅能经 TLS 连接执行网关。主机防火墙只暴露执行网关，不暴露核心执行端或管理端。服务凭据/存储由另一身份管理，AI 没有该主机 shell、文件、容器管理权限。

`deploy/compose.yaml` 提供 core + execution-gateway 两个进程/容器。网关只持有执行能力令牌，未挂载 core 数据，也没有 admin/master 配置；源码不导入 Store。网关只转发精确 `/v1`、`/v2` HTTP与SSH终端WebSocket路由，管理路由和未知路由拒绝。AI 只能接入 execution 网络；不能接入 core-private/outbound，不能运行在具有 Docker socket 或宿主用户 shell 的身份中。

容器网桥连接到宿主发布的 4317 即使地址是宿主 127.0.0.1，也不等于 core 所见的 loopback socket，不能完成首次设置或恢复。容器初始化需要可信容器内的 loopback 浏览器 UI 能力；模板没有提供该浏览器/初始化流程，不是直接启动就可在宿主完成首次设置的部署包。不得通过放宽 Host/Origin/socket 校验或使用接口脚本写密码绕过。部署路径须由可信用户按真实环境设计并验证，本轮没有实施。

仅在现有用户可管理 Docker 的 Mac 启动容器，并没有隔离该用户的无限 shell AI。容器模板仍需要独立主机/受限身份或外部沙箱的实际权限边界。原有 Docker 协议验收只启动测试专属容器并停止，当时未改防火墙、创建系统用户或部署隔离服务；后续 macOS 专用身份安装单独验收。自动化已验证网关路由和角色拒绝，未声称实际容器/操作系统权限验证。

## 剩余边界

文档抓取与手动导入统一检查标题、来源 URL 及其常见编码后的值，拒绝已保管秘密、鉴权 query（含自定义 query 鉴权名称）、URL 用户名/密码和片段；在网络抓取和原子保存之前拒绝。文档正文只过滤已知秘密。校验失败或权威状态未提交时，不改变原文档、版本、鉴权或目标策略；这不是对普通业务数据的 DLP，也不会读取或自动迁移现有真实数据。

新增或更换有效凭据时，按最终配置中的已知秘密重新过滤已有文档正文；正文有变化时更新其文档版本，先原子提交权威状态，再重建 Markdown 导出。导出失败以 `docsExportStatus.status: pending` 明确表示已保存、镜像待重建，不能当作保存失败重放。加载旧状态也在导出前执行这项精确清理。元数据冲突或配置被拒绝时，原状态与导出保持不变。这里处理的是已经保管的凭据副本，不更改普通业务目标、鉴权或路径策略。

元数据的检查覆盖原文、大小写百分号编码、表单 `+` 空格与嵌套百分号编码，最多 8 层、2048 个候选、每候选 8192 字符；超出限额拒绝。标题允许普通 `%`、`C++` 等文本。该有界检查不识别任意未知编码、加密或隐写。保存最终有效凭据时重验全部既有文档元数据，冲突使整次配置更新失败；加载旧库也在重导出前重验，冲突不会自动改写原文件。可信管理员须停止服务并备份后修正冲突的标题或来源，不能让 AI 读取真实库或秘密来修复。

协议 Basic 输出过滤包括 `username:password`、裸组合 Base64 和完整 Authorization 头，Store 的二层过滤使用同一组合规则。该有限集合不能防御恶意目标的任意编码。最终连接地址统一检查所有 DNS 结果，拒绝 broker 自身（包括公网网卡）、已知 metadata 与特殊范围；内网声明只允许正常业务私网范围，开发例外只允许 loopback fixture。

操作期限从 broker 前置解析之前开始，HTTP 与 SSH 的最终解析同样参与期限和取消。底层 OS 的 DNS 作业未必能中止，但等待会及时结束，迟到结果不会恢复请求或启动连接。验证与连接仍使用同一次最终解析的固定地址，不因取消修复重新解析目标。SSH 终端的连接期限在 ready 后清除，已建立会话使用独立会话期限。

- 执行能力持有者可以调用全部已启用且允许的平台接口；本版本没有按 AI 分账户 ACL。只配置该 AI 所需能力或使用独立实例。
- 管理密码泄漏时由用户在 UI 修改，撤销旧会话；重启也会使会话失效。主密钥更换需要离线可信迁移流程，当前未提供自动轮换。
- 本工具不是 HA/数据库集群。每次短写事务持锁重读权威状态、检查 revision、原子提交，页面停留和网络请求不持锁；只读请求刷新状态而不修复磁盘。人工编辑已学习手册也更新连接 revision，旧 AI 清单会冲突而非静默覆盖。每次覆盖更新仅保留一份上一版公开文档，当前与历史正文都过滤已知凭据，元数据同样校验；失败/冲突不推进历史。应用只将历史文字填入当前草稿，再走已有保存和revision检查，不恢复目标/鉴权/规则；默认执行上下文不包含历史正文。锁文件可长期存在，持锁描述符/助手随事务结束释放，不按文件存在或年龄删除。意外中断以 state.json 为准，后续写入重建 Markdown 副本。
- HTTP 内部代理网络必须由部署控制。跨主机公网执行入口需由用户配 TLS 反向代理；不提供内置证书签发或自动购买。
- 正常业务数据按配置发往外部 API；本项目没有 DLP或出网业务审批；SSH能执行管理身份所允许的远端命令，不能访问broker主机。

验证证据必须注明版本、平台、真实安装或临时 fixture。历史 macOS 隔离与 API 实测、2.2.0 临时桌面测试、Windows 策略/协议测试不能互相替代；Windows 真实系统安装整体验收尚未完成。浏览器访问被拒绝时不换路线，未验证的交互如实报告。项目作者：[吉豆茄 jidouqie](https://v.douyin.com/oApPI_L9avQ)。

## 多协议新增边界

Abilock支持受控原生协议子集，见[能力矩阵](../capabilities.md)和各协议文档。管理身份声明independent-target只表示对接目标承诺，不会创建OS隔离。实际连接DNS固定后拒绝broker本机IP、loopback、link-local、metadata；远端内网业务服务可用，必须与broker管理身份隔离。SSH shell/数据库高权限/Docker daemon/Kubernetes/Git server不能读取broker的文件、环境或进程。不能以字段勾选宣称强隔离。

仅信任实际接收鉴权的业务服务；有限输出脱敏无法防止恶意receiver任意重新编码秘密。Git压缩pack/checkout/本地工作区、终端队列和原生协议仍需可信worker的CPU/内存/磁盘/进程配额；模板未部署资源隔离。SSH不提供本机ProxyCommand/LocalCommand/agent，Git隔绝全局config/hooks/helper/filter，数据库拒绝本机元命令与LOCAL INFILE，AWS不读profile/不导出credentials，Kubernetes不执行kubeconfig插件，Docker不调用credential helper。

历史 Docker 协议测试使用合成凭据、loopback 和专属标签，不是安全隔离验收。macOS 本地权限隔离的实际保证和限制见[本地权限隔离](local-isolation.md)，各次报告仅代表其当时的验证范围。

品牌为 Abilock，执行命令仅 `abl`，环境变量前缀为 `ABILOCK_*`。macOS 隔离数据固定在 `/private/var/db/abilock`，可信安装器可内部迁移已知 `~/.abilock` 旧目录；Windows 私有数据位于系统已知的 `%ProgramData%\Abilock\private`，不自动接管未知旧目录。客户端不直接读取私有文件。显式服务部署才使用其配置的 `ABILOCK_DATA_DIR`。聊天快捷声明只能精确绑定已有 POST 路径，不扩大目标或鉴权权限。
