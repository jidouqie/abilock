# 首次使用

Skill 是用户的主要入口，CLI 和 UI 是它依赖的执行与管理能力。目标流程是：检查已有安装 → 完整安装应用、CLI 和 Skill → 用户完成系统授权与首次管理密码设置 → 保存连接 → AI 整理用法 → 按任务调用。日常没有 Abilock 常驻服务。每轮只给当前下一步，公开准备工作由助手处理，密码和凭据交给用户。

## 核对当前状态

先复用已知程序位置，检查公开命令与版本。`abl --help` 可确认入口，没有 `abl --version` 命令。macOS 的 `/usr/local/bin/abl` 可能是固定 wrapper，也可能由旧 npm 链接指向它，不能机械地把命令上级目录当作 npm 包。

- macOS 受保护版本：`/usr/local/libexec/abilock/manifest.json` 的 `runtimeVersion` 或 `runtime/package.json`。
- Windows 受保护版本：`%ProgramFiles%\Abilock\windows-installation.json` 或 `runtime\package.json`。
- 其他客户端：从已确认的公开程序路径核对 `package.json` 中的包名、版本和 `bin`。

当前源版本为 2.2.11，实际使用版本和构建以安装元数据为准。同版本开发更新还需核对公开 manifest 摘要；明确覆盖安装时使用完整包的 Install.command，不能仅凭相同版本号断言已更新。摘要证明完整性，不单独证明发布者可信。只检查公开文件，不搜索 home、私有启动配置或凭据库。

## 从项目源码准备（macOS）

项目仓库为 https://github.com/jidouqie/abilock，当前是私有源码仓库；需要用户已有 GitHub 访问权限。本次未提供在线二进制 Release 或 npm 包，不猜测下载地址。已有连接的用户先检查安装状态，已可使用时直接进入任务，不重复安装。

源码路线需要已有 GitHub CLI 登录、Git、Node.js ≥22.12、npm、macOS 13+、Python 3 和 Apple 命令行工具。由助手检查这些公开依赖，不读取认证配置或令牌。缺少账号权限、需要登录或系统确认时，明确交给用户处理，不自行创建长期认证。

在无同名目录的位置运行：

```sh
gh repo clone jidouqie/abilock && node abilock/scripts/install-from-source.mjs
```

已有可信检出时，在仓库运行 `node scripts/install-from-source.mjs --check` 只检查依赖与已提交源码，`--prepare-only` 构建并校验公开包而不检查现有安装状态；不带参数才做完整安装预检和安装。入口使用当前干净提交在临时目录构建并校验，成功后交给相同的 `Install.command`，不是绕过安装器或权限的替代路径。版本与完整性、依赖下载或测试失败时停止，不能改用未验证的替代包。实际下载、构建和管理员授权需要时间与用户配合，不承诺一句提示词在任何宿主都能全自动完成。

## 新用户完整安装

优先使用明确提供的对应平台完整包。它包含独立 Node、生产依赖、应用、CLI、Skill 和安装组件，用户无需先安装 Node/npm。只有 Skill 文本或 Python wheel 不能替代完整安装；当前 Python 包仍是需要 Node 的远程客户端。

### macOS

代码支持 macOS 13+ 的 Apple Silicon 和 Intel，本次本机完整安装验收为 ARM64；Intel 需对应架构构建及独立验收。打开包根目录的 `Install.command`；安装器会先核对公开包、同名冲突、系统 Python 3 和 Apple 命令行工具。缺项先说明并解决，不反复弹系统授权，不自动关闭系统安全设置。

一次正常安装将固定程序放入 `/usr/local/libexec/abilock`，注册 `/usr/local/bin/abl`，并给安装用户注册 `~/Applications/Abilock.app`。当前用户的 Codex、Claude 和通用 Agents Skill 入口指向同一份受保护 Skill。已知旧 npm 命令链接可转向固定 wrapper，旧 npm 包不删除；未知同名工具或应用在授权前停止，同产品 Skill 目录先保留备份。

完整包已带依赖；不要让用户再跑 npm。原有 CLI 用户的 `abl config` 安装/升级路线保留，见后面的兼容路线。

### Windows

代码目标为 Windows 10 x64、Windows 11 x64 / ARM64。完整包带 Node；x64 系统还需 .NET Framework 4.8，ARM64 系统需 4.8.1，两者均需 WebView2。缺项在授权前明确说明，不能把启动请求当成窗口加载成功。

核验完整包后运行以下英文命令；路径由助手替换为已确认的解压位置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Path\To\Abilock\Install-Abilock.ps1" -BundlePath "C:\Path\To\Abilock" -Check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Path\To\Abilock\Install-Abilock.ps1" -BundlePath "C:\Path\To\Abilock"
```

PowerShell 7.6 可使用 `pwsh.exe`，参数相同。`-ExecutionPolicy Bypass` 只用于本次已核验安装进程，不运行 `Set-ExecutionPolicy` 修改系统策略。预检不改系统。正常安装请求一次 UAC，代码目标是同时安装受保护程序、`abl.cmd`、独立应用、开始菜单入口与原安装用户的 Skill 入口。应用位于 `%ProgramFiles%\Abilock\desktop\Abilock.exe`，CLI 位于 `runtime\bin`；安装器只向安装用户的 PATH 添加本产品目录，并创建该用户开始菜单入口；不改系统 PATH 或其他用户入口。同名未知快捷方式或 Skill 在授权前停止。

脚本全部为英文 ASCII，语法兼容 Windows PowerShell 5.1。PowerShell 7.x 进入同一个预检流程；实际变更交给系统 5.1，已提升进程转交时不重复请求 UAC。系统架构在授权前核对，默认选择原生包；ARM64 包不能在 x64 上安装，Windows 11 ARM64 可使用 x64 仿真包。

此前 PowerShell 5.1.26100.9711、7.4.21、7.5.12、7.6.7 的兼容矩阵各通过 142 项检查；新包仍需运行对应回归。这不是对未来所有版本的保证。Windows 已完成临时包、假值、原生策略与协议测试，用户也已在 ARM64 实际窗口确认合成页面加载，以及关闭后 worker 和 WebView2 退出。首次安装必须核对实际回执，再用普通用户令牌完成专用 SID、按需任务、假值调用和退出检查。管理员 SSH 的测试不能证明普通用户隔离；只完成临时测试时不能报告本机安装已验收。升级回滚、真实供应商及其他机器仍需各自证据。

### Skill 加载

完整安装注册原安装用户的 `.codex/skills/abilock` 与 `.claude/skills/abilock`；macOS 还注册 `.agents/skills/abilock`。以安装器实际完成回执和公开路径复核为准。宿主可能需要重新加载 Skill 或新开对话。仅复制目录、出现命令帮助或请求打开应用都不等于连接已配置。

如分发物只是 Skill ZIP，先核对其 `assets/runtime-manifest.json` 和 `assets/abilock-runtime.tgz`。这个 tgz 是 Node 程序包，不自动等同于 Windows 完整安装包；缺少对应平台完整包时说明缺项，不编造地址或从尚未发布的 npm 包名安装。

## 原有 Node CLI 兼容路线

仅在复用原有 Node 客户端或明确的源码开发场景使用。客户端需要 Node.js ≥22.12；可信 tgz 可由助手安装到已授权的可写目录。确认无同名冲突后才注册全局命令，不用 `sudo npm install`：

```sh
npm install --global --ignore-scripts --registry=https://registry.npmjs.org "/absolute/path/abilock-runtime.tgz"
abl --help
```

全局目录不可写时，使用用户选定的新目录并给出明确的包内入口；不声称全局 `abl` 已就绪，不静默改 shell 配置。macOS 更新客户端后，`abl config` 可检查并升级受保护程序；Windows 仍需完整平台包安装器。源码构建不是普通用户完整安装的必选步骤。

## 用户保存连接

1. 用户打开 Abilock 或运行 `abl app`。首次新实例在受保护窗口设置 Abilock 管理密码；它与系统管理员密码不同，均不发到对话里。已有安装沿用原管理密码。
2. 登录后在“连接”点“添加”，选择类型，填写必要信息。API 填别名、固定地址、鉴权、凭据和可选文档链接；SSH、数据库等只解释该协议需要的字段。
3. 用户在页面粘贴私钥或选择本地私钥文件。文件进入当前配置表单，通过原保存接口提交，不单独上传或记录日志。助手不读取真实私钥确认。
4. 保存后可保持应用打开，让 AI 直接学习。应用关闭只结束自己的配置进程；业务 CLI 独立运行。

`abl config` 保留临时浏览器模式：macOS 指定用户自己的 Chrome，其他系统使用系统打开入口；在终端 Ctrl+C 结束，关标签页不等于退出。浏览器打开失败只提供公开地址，不换工具或路线绕过。浏览器协助遵守当前宿主许可；用户输入秘密时交还操作，不截图或读取凭据。

| 字段 | 内容 |
|---|---|
| 别名 | 字母开头，字母/数字/`_`/`-`，最多 32 字符；不区分大小写且不能重复 |
| 备注 | 可选，最多 200 字，用于区分账号或用途；列表和 AI 目录可搜索，调用仍用别名 |
| 地址 | 固定业务目标，可包含官方 API 前缀；不是文档网站地址 |
| 鉴权 | 按厂商实际方式选择；Header/Query 的字段名是公开信息 |
| 凭据 | 用户填写；已有值留空保留，输入新值替换 |
| 文档 | 可选官方公开链接，供 AI 整理手册 |

不让用户编写路径规则、模型清单、JSON 或能力矩阵。别名可改，密钥和手册保留；保存后用新别名。文档来源或协议目标、身份、数据库、路径、命名空间变化时，旧手册标为待更新；API 地址或鉴权变化时接口规则清空、手册保留并标为待更新；改名和仅轮换密码保留有效手册。自建的 S3 兼容存储或 Registry 位于内网时，在连接选项中勾选“内网连接”，必要时填写 CA 证书。

2.2.11 的连接测试覆盖 API 和各协议，区分鉴权通过、服务响应和未验证。API 优先使用已核验的官方只读接口，未适配地址不自动调用模型；对象存储可能产生一次请求费用，需单独确认。SSH 测试要求先保存从可信渠道取得的主机指纹，未知或变化时拒绝，仅验证握手与登录，不运行命令或文件操作。普通直接 SSH 的既有兼容策略未改变，Git SSH 的指纹字段独立保留。先保存修改再测试。不能把执行器本机、其 Docker daemon 或能管理执行器的集群作为业务目标。普通文档不能安装插件或改身份/权限。

## AI 学习与人的修改

先读取公开 `documentationUrl`、现有手册和版本，再按[学习用法](learning.md)整理。手册是自由 Markdown，AI 负责正常编写和维护，人可以在应用中修改标题、正文。 每次覆盖更新保留一份上一版，可在应用查看或填入当前草稿，普通保存确认后才生效；不改目标、鉴权或规则。默认 CLI 只给当前正文，不加载历史内容。不能要求用户先写完整手册再上传；来源、覆盖范围与未验证内容应如实保留。

HTTP 学习可登记有证据的方法和路径；协议学习仅更新用法，不改变目标、鉴权或权限。缺页、登录限制或账号专属模型未知时说明缺项，不猜、不用凭据抓文档，不进行收费试探。

应用和 CLI 共用短事务与版本检查。人正在看页面不会阻塞学习；`CONFIG_BUSY` 只表示实际写事务尚未完成，等待后重读公开状态。`REVISION_CONFLICT` 时合并最新内容，特别保留人工微调，不能拿旧清单换版本号重发。锁文件可长期存在，不删除解锁。

`DOCUMENT_EXPORT_PENDING` 表示权威内容已保存，仅 Markdown 副本待重建；读取新版本继续，下次保存或打开配置时自动修复。

```sh
abl list --json
abl doc DS --json
abl doc ssh SERVER --json
```

目录的 `configured` 是配置状态，`saved` 是手册状态，均不证明账户权限或真实调用成功。缺密钥、停用或不可用的连接由用户在页面处理。

## 调用并退出

使用当前授权和手册选择最小业务调用。学习不自动授权生成、删除、上传或发布；已授权的任务直接继续，不重复确认。例子：

```sh
abl api DS chat '把这段文案改得自然些，保留事实。' --json
abl ssh SERVER 'uname -a' --abl-json
abl mysql DB 'SELECT 1' --abl-json
```

其他 API 请求由 AI 生成 `{method,path,body,...}`，用 `--file` 或 stdin 提交，不让用户写 JSON。普通调用结束后退出，交互 SSH 在会话结束后退出。厂商异步任务在上游继续运行时，本地提交命令仍可退出。

HTTP 默认及最大 `timeoutMs` 为 420000（7 分钟），CLI 外层最多等待 435000 毫秒以取消收尾；普通协议仍默认 30000、最多 120000。客户端和受保护运行包都要支持该版本，单独更新 Skill 不能证明已生效。

长 HTTP 请求用 `--abl-progress` 查看 stderr 等待/接收状态。厂商支持时按手册启用 SSE；默认 stdout 流式输出，`--json` 等完整响应。超过 7 分钟仍终止，更长任务使用已证实的异步接口。超时、取消、结果未知或批次部分成功后先核对上游状态，不自动重复提交。

## 升级与恢复

等待活动调用结束，正常关闭应用或旧配置终端，再运行可信完整包的同一安装入口。macOS 原有 CLI 可通过 `abl config` 升级；Windows 用 `Install-Abilock.ps1`。系统授权只限本产品安装，不给 AI 任意管理员权限。

安装器保留既有身份、主密钥、管理密码、连接和手册。中断时重新运行相应可信入口，由安装器核对受保护事务并恢复；不知道归属的账号、目录或记录保持不动并停止。不手动清理恢复材料，不为了排障重新生成主密钥。

Windows 2.2.3 若在首次管道初始化前中断，保留原包、专用账号、事务和私有目录。2.2.7 的可信安装器提供受限续装参数 `-RepairFromBundle` / `-RepairFromManifestSha256`，同时核对新旧清单、原账号 SID、事务标记与任务归属后，只替换公开程序。助手准备好固定摘要的入口再交用户运行；不能单独覆盖 Host、改写事务摘要或清空数据。旧版本公开安装信息不可读时，只有已核验原 2.2.3 清单的配对修复会把该项留到管理员阶段重新完整检查；这不代表旧安装已通过全部预检。2.2.6 若在首次初始化时中断，使用它的原始配对清单继续，并保留此前 2.2.3 的受保护备份。不要把 Windows 自动创建的 AppData 当作未知应用数据，也不要自行删除它。原授权进程已结束时，后续修复仍需一次新的系统授权，不能承诺可复用已退出的授权进程。

密码遗失和数据损坏不是“重新安装即可修复”。助手只核对公开状态，交可信管理员按正式恢复文档处理，没有 CLI 重置或秘密导出入口。

## 停用与卸载

目前没有自动卸载或一键清空命令。移除 Skill 或应用入口不删除受保护程序及用户数据；完整卸载需可信管理员明确本产品身份与路径，先确定数据保留/备份方案。用户说卸载不等于授权清空连接、凭据、手册、经验和安装备份。不要用删除私有目录、身份、锁或主密钥排查故障。

## 显式远程模式

用户明确选择已有网关时，才使用已授权的 `ABILOCK_ENDPOINT` / `ABILOCK_EXEC_TOKEN`。这些是执行能力，不是厂商 Key，不贴对话或放进命令参数。远程 `config` 只打开已有管理地址；`learn` 仍只支持完整本地程序，不改走管理 HTTP 接口。Linux 没有当前本地隔离安装器，不静默降级为同用户模式。

Windows 2.2.8 修复普通请求的输入缓冲：小请求不再等待输入关闭后才转发。已初始化的 2.2.7 使用普通升级，不传续装参数，也不重设管理密码。2.2.3、2.2.6 的未完成安装使用明确配对的 2.2.7 恢复包，完成后再升级；不能把版本号或清单摘要替换为未支持的恢复组合。
